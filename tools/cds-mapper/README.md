# CDS Mapper helper artifacts

Details on the CDS Mapper and these artifacts are available in the [SAP Community blog post](https://community.sap.com/t5/technology-blog-posts-by-sap/sap-table-to-cds-mapper-new-version-thanks-to-ai-supported-development/ba-p/14510087).

The artifacts in this directory are generated by CDS Mapper and are independent of the ABAP and BTP components in this repository.

## Full-scan analysis

The full-scan report can be hosted directly on GitHub Pages, so readers can open it in their browser without downloading a ZIP. After Pages is enabled and the report workflow deploys, use the [online CDS Mapper report](https://sap.github.io/project-kernseife/cds-mapper/).

`table-cds-mapper-analysis.zip` remains available for offline use.

1. Extract the archive to a local directory.
2. Open `table-to-cds-mapper.html` in a modern web browser.
3. Keep the adjacent `table-to-cds-mapper-data/` directory intact; it contains the report data loaded by the HTML file.

The archive contains 257 files: the report HTML document and 256 JavaScript data files.

### Hosting and preview

In repository **Settings → Pages**, choose **GitHub Actions** as the build/deployment source. The `CDS Mapper report` workflow builds the archive on pull requests and publishes it from `main`; it can also be run manually from `main`. Setting up Pages requires a repository administrator. A deployment supplies its actual site URL through the `github-pages` environment; the link above uses GitHub's default project URL.

To preview locally, with Python 3 installed:

```sh
python3 tools/cds-mapper/build-pages.py
python3 -m http.server 8000 --directory _site
```

Open `http://localhost:8000/cds-mapper/`. The build uses a new output directory, preserves the HTML and data bytes from the checked-in archive, and keeps all data shards beside the report. No ABAP/BTP deployment or external runtime dependency is needed.

## External classification import

`classification-good-c1-candidates-bf5.zip` contains 2,071 external-classification JSON records for standard database tables with good CDS-successor candidates. Import the archive through the External Classification import in Kernseife.

Each ZIP entry uses the `.TABL.json` naming convention expected by the import and contains one classification record with an empty `labels` array.
